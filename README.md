# Pikmin 明信片收藏（Pikmin Universe）

個人使用的網頁應用，用來整理與追蹤 Pikmin Bloom 的明信片收藏：誰送給我、我送給誰、還有誰在等我回覆。

> 這是個人愛好者專案，與任天堂（Nintendo）、Niantic 無關。Pikmin、Pikmin Bloom 為其商標或著作。
> 本專案未使用任何官方圖像，網站圖示為原創設計。

線上版本：https://serendipity-all.github.io/pikmin-universe/

---

## 架構

| 部分 | 內容 | 放在哪裡 |
|---|---|---|
| 前端 | 單一 HTML 檔，不需建置；瀏覽器本機暫存 | 本倉庫，由 GitHub Pages 提供 |
| 後端 | Google Apps Script（網頁應用程式） | Apps Script，**不在本倉庫** |
| 資料 | Google 試算表：Cards、Friends、Snapshots、PendingReplies、Settings | Google 雲端硬碟 |
| 照片 | Google 雲端硬碟資料夾（可含子資料夾） | Google 雲端硬碟 |
| AI 辨識 | Google Gemini API，多個模型自動切換 | 由 Apps Script 呼叫；金鑰只存在 Apps Script |

資料流：網頁 ⇄ Apps Script ⇄ 試算表／雲端硬碟。網頁同步時是**整份覆蓋**。

---

## 主要功能（v3.0）

- **明信片庫**：島嶼（依取得國家分島）、卡片、列表三種檢視；搜尋、多條件篩選、排序
- **好友**：好友 ID 制、別名、合併好友、標籤、島嶼／格狀檢視、依最近收到／送出排序
- **待回覆**：依好友分組、最久未回前三名標記、超過 14 天警示、顯示對方最新送的明信片
- **快照**：探險快照等遊戲截圖，可用 AI 辨識類型與資訊
- **AI 辨識**：從明信片圖片預填名稱、地點、取得方式、標籤；Gemini 免費額度用完時自動換模型
- **雲端硬碟掃描**：掃描子資料夾中的新照片，可選擇要掃的資料夾
- **外觀**：政策島風格（六角島嶼）；網站圖示可選或上傳自己的圖片
- **資料管理**：JSON 匯出／匯入

## 版本與 GAS 對照

GAS 不在 git 裡，由 Apps Script 自己管理版本，所以在這裡記錄每個網頁版本搭配哪一個 GAS 部署版本。

| 網頁版本 | Git tag | Apps Script 部署版本 | 說明 |
|---|---|---|---|
| v3.0 | `v3.0` | **58** | 島嶼風格、可選圖示、手機效能改善、好友排序修正 |
| v2.0 | `v2.0` | 與 v3.0 相同 | 穩定基礎版 |
| v1.0 | — | — | 原始版（2026-04） |

規劃中：v3.1 — 新照片自動偵測與探險快照歸屬（會新增一份 GAS，部署後在此表回填版本號）。

版本規則：大版（X.0）為風格或架構的重大改版；小版（X.Y）為新增功能；修訂（X.Y.Z）為 bug 修正。

## 部署與更新

**網頁**
1. 新版先用新檔名上傳到 `main`（例如 `pikmin-postcards-v3_YYMMDD.html`），用 `…/pikmin-universe/檔名` 測試，不影響平常使用的版本。
2. 手機與電腦都測過後，將定案檔案另存成 `index.html` 上傳覆蓋。
3. 建立 Release，打上對應的 tag（例如 `v3.0`）。要先上傳再打 tag，tag 才會包含該版本。

**GAS（Apps Script）**
1. 修改程式碼後，**必須重新部署才會生效**。
2. 部署 → 管理部署作業 → 編輯 → 版本選「新版本」→ 在說明欄寫上對應的網頁版本 → 部署。網址不會改變。
3. 把新的部署版本號回填到上面的對照表。

---

## 回復舊版

**網頁**
- 到 Releases 找到要回復的 tag，下載 Source code (zip)，取出 `index.html` 重新上傳覆蓋；或用指令：
  ```
  git checkout v2.0 -- index.html
  git commit -m "回復到 v2.0"
  git push
  ```
- 重新整理頁面；手機有時要清掉網站快取才會看到變更。

**GAS**
- Apps Script → 部署 → 管理部署作業 → 編輯 → 版本選舊的（例如 58）→ 部署。

## 注意事項

- **同步是整份覆蓋**：不要同時開兩個分頁或兩個版本各自存檔，後存的會蓋掉先存的。
- **v2.0 與 v3.0 共用同一份資料**。v2.0 同步時不認得 v3.0 的圖示設定，會把雲端上的圖示選擇清掉；交替使用兩版時，v3.0 下次存檔會重新寫回。
- **自訂圖示**存在 Settings 工作表，有容量上限（約 3～8 張）。
- **不要把機密寫進公開倉庫**：Gemini API 金鑰、試算表與資料夾的識別碼、GAS 網址都不要放進 README 或 HTML。
- 建議定期用「設定 → 資料管理」匯出 JSON 備份。
